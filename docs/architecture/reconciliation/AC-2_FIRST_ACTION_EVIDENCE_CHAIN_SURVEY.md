## 2. Block 2 — canonical risk governance (implemented)
- One authoritative definition: `CANONICAL_BASE_RISK_CLASS` in `handoff-contracts/src/authorized-action-package/canonical-actions.ts`, next to the other per-type governance sets (`SIMULATION_NOT_APPLICABLE_ALLOWED`, `STRUCTURED_ADI_PROPOSAL_REQUIRED`): `inventory_reorder_policy_update@1` → `medium`. Per `code@schemaVersion`, never global. It is deliberately **not** a field of `ActionTypeContract`: that interface is compared with workspace-stored definitions and the existing governance sets already live beside it, so a second registry is not created and the stored-definition comparison is untouched.
- ADI does not classify: `deriveRiskClass` (P0-3) gains one input, `canonicalBaseRisk`, a deterministic floor (MAX with persisted severities, generator level, human raise — contextual evidence can only raise it). The producer passes `canonicalBaseRiskClass(...)`; it contains no risk literal (guard test).
- ABA consumes it: `packageIssuancePolicy` refuses (`RISK_POLICY`) a package whose persisted recommendation risk is *below* the action type's canonical base. Unclassified keeps its P0-2 meaning (treated as high, never below a base). The package still records the persisted class; no `aap/1` change.
- Effect on the approval tier: producer-made proposals are now `medium` (required approver tier 2) instead of unclassified/high (tier 3). Test fixtures that used `low` for this action type were updated to `medium` (shared `issuanceFixture`, API `APPROVABLE_FACTS`).

## 3. STOP-AND-REPORT — why Blocks 3–10 were not started
The block text says to stop if the source data cannot be ingested through an existing authoritative DAL path without inventing a new source of truth, and the principal proof forbids direct BO seeding. Four inputs cannot be obtained that way, and two of the four are *deliberate* prior owner rulings:
1. **Item and warehouse identity** have no writer at all. Adding `inventory_item` / `warehouse` mappers plus BO commands extends the existing mapper path (BO stays the truth) but creates a new canonical-entity creation path — a design decision, not a test fixture.
2. **Baseline reorder policy.** A balance created by DAL movements is 0/0/UNSET, and the producer correctly returns no recommendation for an unset baseline (`FIRST_CONFIGURATION_OPTION = NO`). The block asks for "existing reorder policy state" through DAL, but Block E (owner-ruled) forbids the intake path from configuring it. These two cannot both hold.
3. **Declared currency** is a business-admin act by Block C, not a DAL fact.
4. **SIM→ADI.** The locked package chain is BO→BI→DT→SIM→ADI; ADI's package intake takes a Simulation publication package. Under C-1 no simulation exists for this action, so a *package-intake* ADI entry cannot be satisfied without fabricating one. AC-1's producer writes ADI records directly; Block 7 must say whether the BI/BDT boundary is a producer precondition (my proposal) or whether ADI intake is to be amended.
