## Final owner decisions — proposed specifics, each still requires explicit ratification

### H-RET — retention, deletion and minimization
**Recommended decision:** Audit only metadata, scoped IDs, hashed evidence and refusal codes; exclude raw customer facts, credentials and financial payloads. No background purging before a jurisdiction-specific legal/privacy retention schedule and erasure-exception process is approved. An approved schedule must define data categories, controller, lawful basis, minimum/maximum duration, DSAR and litigation hold. **Still open:** jurisdiction, legal retention term and deletion exceptions; no duration is presumed.

### H-HASH — canonical encoding, signatures and anchoring
**Recommended decision:** Adopt versioned byte-canonical encoding and domain-separated SHA-256; digest generated by the trusted writer (not caller). Store predecessor hash and deterministic sequence per scoped control stream. Periodically anchor signed head hashes outside the database with custody separated from database administrators. **Still open:** canonical byte-level encoding specification, key provider and custodian, signing/rotation cadence, anchor interval, verification/recovery and compromise response. Self-consistent hash chains are not proof against database-owner rewrites without independently protected anchors.

### H-AUTH — identity, permissions and tenant scopes
**Recommended decision:** Authoritative identity-session principal only; ABA owner issues an explicit current, business-scoped `cl:shadow:evaluate` assignment/version with verified grant provenance. An independent approver is verified at decision time. No delegation, no role inheritance, no caller IDs as proof. CL consumes a read-only ABA authority port; a narrowly granted database writer enforces matching composite tenant/workspace/business/assignment scope with FORCE RLS and database-clock revocation/expiry checks in the atomic transaction. **Still open:** exact issuer API, permission representation, database roles, security-definer boundary and composite FK design.

### H-TXN — state, idempotency and concurrency
**Recommended decision:** CL owns the shadow-control state and append-only audit transitions. Lock the scoped control row and canonical authority version within a single transaction; same scoped idempotency key and identical canonical input replays original result; changed input with same key refuses. Failure of audit append aborts control transition. Control state remains default disabled until explicitly approved and independently verified. **Still open:** canonical control-state schema/version, lock order, operation key scope, event numbering, transaction retry policy and revocation races.

### H-KILL — emergency switch and revocation custody
**Recommended decision:** Kill switch defaults to deny and outranks all decisions. Only separately authorized security/incident custodians may clear it with two-person approval and an append-only auditable decision. Any authority-revocation event forces effective denial before the next evaluation; failures of custody/revocation services refuse. **Still open:** named custodians, on-call escalation, switch storage/replication, recovery quorum, incident SLA and out-of-band shutdown mechanism.
